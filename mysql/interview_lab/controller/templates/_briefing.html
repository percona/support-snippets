What this is

A hands-on test. You get {{ max_level }} questions, one at a time, on real MySQL servers. Each one is a problem a customer might actually raise: a server that will not start, replication that has stopped, a slow query.

You have {{ '%.1f'|format(duration_seconds / 3600) }} hours. The clock starts when you press the button at the bottom of this page — not before.

The questions get harder as you go. The last one is a written assessment rather than a fix — leave about 20 minutes for it.

Your screen

The problem is on the left. Your servers are on the right. The clock and the Send button are at the top.

Working on more than one server

Each tab is a separate server. Click a tab to move between them. The + button opens another terminal and asks which server it should connect to — handy for watching a log on one server while you work on another, or for a second shell on the same one.

You can also reach the others from inside a shell: mysql -h node2

Writing files

Typing a long statement into a terminal is slow and easy to get wrong. The Files tab lets you write it in a proper editor instead, save it to /home/candidate, and then use it:

mysql < repl.sql

Any kind of file works — .sql, .txt, .md, or no extension at all. When a question asks you to write a particular file, the name is filled in for you.

Finishing a question

Press Send at the top right. Your work is checked on the server, and you move to the next question.

You cannot go back to a question once you have moved on, so make sure you are happy before you press Send. You are not told whether you passed — keep going either way.

The check can take up to about 40 seconds. Leave the page alone while it runs — do not reload or close the tab.

When the clock reaches 0:00 nothing stops: a red banner appears, the timer counts upwards, and you can keep working and still press Send. The extra time is visible to your interviewer.

Copy and paste

You cannot select or copy text from the question or from a terminal, and you cannot paste into a terminal: type your commands there. The Files editor is the one place where selecting, copying and pasting work — for example a statement you looked up in the documentation — and every save there is recorded, including where any pasted text came from.

Type at your own pace. Input that no hand produces — text arriving in one piece, or keys faster or more evenly than a person types — is rejected and locks your session until the interviewer decides whether to unlock it. The interviewer sees when it happened and why. Dictation and text-expander tools trigger it too, so don't use them here.

Using AI is not allowed

Do not use AI assistants or AI agents of any kind during this test — no chat assistants, no coding assistants, no AI browser extensions, and nothing driving this page for you.

The official documentation and search engines are fine. Looking things up is a normal part of the job and we expect you to do it. What we are measuring is how you diagnose and fix a real system, which is not something an assistant can do for you on a customer call.

Your interviewer can watch your terminals live while you work, and the whole session is recorded, including what you type and anything pasted into the editor. If you get stuck, say so, or write what you tried and what you think is going on into a notes.txt in the Files tab and save it — the save is recorded with your session. A partly finished answer with good reasoning is worth far more than one you did not arrive at yourself.

If something looks broken

Some questions start with something genuinely broken — that is the point. But if the page itself stops responding, or a terminal will not open, tell your interviewer rather than working around it.
